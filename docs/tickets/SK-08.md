# SK-08 — Continuous quiet tone and service trial

**Status:** Implementation, installation, and live routing/cleanup verified;
physical keepalive outcome pending user observation.
**Authorization:** User-approved plan on 2026-10-07 after reporting intermittent
speaker shutdowns without a clear pattern. Add a continuous low-amplitude tone
and use it in the existing login service. This is a signal-continuity experiment,
not proof that pulse gaps caused shutdowns or authorization for deferred milestones.

## Delivered behavior

- `run --mode tone` defaults to 100 Hz / PCM peak amplitude 0.0005; frequency and
  volume retain existing finite/range validation. Interval and duration conflict
  with tone mode. Plain `run` retains pulses; digital silence and one-shot `test`
  retain their behavior.
- A bounded oscillator generates 48 kHz stereo native-endian f32 into a fixed
  16 KiB buffer, preserving phase between chunks. Each stream starts with a single
  10 ms fade-in; chunks do not repeat fades. Zero amplitude yields positive zeros.
- The process transport refills only after all current bytes are written.
  Tone and silence share continuous playback lifecycle, ten-second no-progress
  watchdog, thirty-second failure retry, bounded diagnostics, and cancellation.
  Cleanup remains immediate/bounded rather than waiting for an audio fade-out.
- The service runs `run --mode tone --frequency 100 --volume 0.0005` on the default
  output. No new dependencies, configuration system, device selection, or activity
  detection. README covers usage, the trial, and rollback to pulse `ExecStart`.

The end-to-end tone PCM test was run before implementation and failed because no
continuous tone stream was produced. After implementation it passed for defaults,
137.25 Hz / 0.001, and zero amplitude. It captures multiple chunks through uneven

single startup fade, then verifies one child and cleanup.

**52 tests passed:** 36 unit and 16 integration. Coverage includes seamless PCM,
CLI contracts, backpressure, noisy/stalled readers, early exit, SIGTERM-resistant
child cleanup, interruptible retries, and actual thirty-second restart waits for
