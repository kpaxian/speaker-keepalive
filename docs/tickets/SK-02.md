### Changes and interfaces

- `src/backend.rs` now implements `play_once`, native-endian PCM encoding,
  capability checks, and the structured `pw-play` invocation. `Backend::check`
  runs bounded `--help` and `--list-formats` probes before playback.
- `Backend::play(pcm, duration, cancellation)` sends a borrowed cached byte
  buffer and waits for successful child completion. It returns bounded captured
  diagnostics or an actionable I/O error; it never retries one-shot failures.
- `src/backend/process.rs` owns nonblocking stdin/stdout/stderr, poll-driven
  transfers, deadlines, cancellation, termination, and reaping. Partial writes
  retain their offset; EOF closes stdin. A quota on output drainage prevents
  continuous stderr output from starving cancellation/deadline checks.
- `Cancellation` shares an atomic flag with the `ctrlc` handler. The CLI treats
  handled cancellation as exit 0, without normal output; `--verbose` reports
  cleanup. Input errors still exit 2 and backend failures exit 1. A cleanup error
  is a failure, even when the original event was cancellation.
- The child gets its own process group. Ctrl+C reaches the parent, which owns
  cleanup. Closing stdin precedes SIGTERM; SIGKILL follows if grace expires.
  A drop guard also kills/reaps on setup failure or unwinding.
- Added backend unit/integration coverage plus a Python fake executable under
  `tests/support/`. It records bytes, arguments, and PIDs without audio access.
  CLI tests use a fixture-only or nonexistent PATH and cannot fall back to the
  system audio tool. PID checks verify children are absent, including zombies.
- Updated the README, dependencies/lockfile, and ticket states. Removed only
  the temporary integration expectation that `test` was unimplemented.

### Verified transport and dependencies

Installed `pw-play` reports PipeWire 1.6.9; Fedora's package owning the executable
is `pipewire-utils-1.6.9-1.fc44.x86_64`. Verified without opening an audio stream:

```bash
pw-play --version
pw-play --help
pw-play --list-formats
pw-play --raw --format f32 --rate 48000 --channels 2 --volume 1 --help
rpm -qf /usr/bin/pw-play
```

The local man page confirms raw stdin support. PipeWire 1.6.9's
[pw-cat source](https://github.com/PipeWire/pipewire/blob/1.6.9/src/tools/pw-cat.c)
maps `f32` to `SPA_AUDIO_FORMAT_F32` and reads raw frames directly from stdin;
the [format aliases](https://github.com/PipeWire/pipewire/blob/1.6.9/spa/include/spa/param/audio/raw.h)
define native endianness. Samples therefore use `f32::to_ne_bytes()` and the
invocation is:

```text
pw-play --raw --format f32 --rate 48000 --channels 2 --volume 1 -
```

Amplitude remains applied exactly once in audio generation. No temporary WAV,
shell command construction, device selection, or system volume change was added.

- Added `ctrlc = 3.4.5` for the interrupt handler.
- Chose `nix = 0.29.0` with fs/poll/signal/process support rather than the plan's
  suggested rustix: ctrlc already depends on nix, so the safe Unix I/O/signal
  wrappers reuse an existing dependency. No custom unsafe code or async runtime.
- `/usr/bin/python3` is required only by fake-backend tests, not the application.

### Limits and behavior for later tickets

| Behavior | Implemented limit |
| --- | --- |
| Each capability probe | 2 seconds, then cleanup if needed |
| One-shot playback | Pulse duration + 10 seconds, then cleanup if needed |
| No audio-write progress | 10 seconds while input remains pending |
| Active I/O poll wait | At most 100 ms |
| Graceful termination | 500 ms after SIGTERM, then SIGKILL and reap |
| Retained stderr | 8 KiB; continue draining, mark truncation |
| Retained probe stdout | 32 KiB; oversized capability output is an error |

`Limits` permits omitting the overall deadline while retaining the no-progress
watchdog; a test exercises that case. The current transfer API still accepts
finite input. SK-04 must add fixed-buffer refill for continuous silence, reusing
the process ownership, polling, diagnostics, and watchdog instead of claiming
continuous streaming already exists.
