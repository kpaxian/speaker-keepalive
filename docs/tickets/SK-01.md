- Use integer interval seconds/duration milliseconds and finite floating-point

  silence mode; `test` accepts neither mode nor interval.

  end, shortened where necessary. Explain PCM amplitude in CLI help.

### Interfaces and decisions

- `Cli::into_operation()` yields `Test(PulseParameters)`,
  `RunPulse { interval: Duration, signal: PulseParameters }`, or `RunSilence`.
  Global `verbose` is passed separately by the entrypoint.
- Omitted settings use spec defaults. Explicit pulse settings conflict with
  silence mode, including zero amplitude or values equal to defaults. `test`
  has no interval/mode option. Input errors exit 2, pending playback exits 1,
  and help/version exit 0.
- `PulseParameters::new(duration_ms, frequency_hz, amplitude)` validates private
  fields; `duration()` exposes the duration for interval validation.
  `generate()` returns an interleaved `Vec<f32>` at 48 kHz with two identical
  channels. It does not serialize bytes or write a file.
- Default generation is 14,400 frames / 28,800 samples / 115,200 bytes. The
  maximum supported pulse occupies 1,920,000 sample bytes. Both endpoints are
  zero; fades are at most 480 frame intervals (10 ms), reduced to 479 for a
  20 ms pulse to keep ramps disjoint. Zero amplitude returns all-zero bits.
- The only direct dependency is clap 4.5.20, with derive/help/usage/validation
  support and no color feature. It supplies correct option handling and useful
  errors without a custom parser. Runtime/process dependencies are deferred.
- Small organizational deviation: CLI parsing has its own `src/cli.rs` because
  it already has independent validation responsibilities and tests. No config
  module or later-milestone functionality was added.

### Environment limitation and workaround

The initial online `cargo test` failed because Cargo could not resolve
`index.crates.io`. Direct `curl` downloads worked. Eleven dependency archives
were assembled under ignored `.cache/vendor`, with SHA-256 checksums verified
against registry metadata; existing cached archives were reused where available.
An ignored `.cache/cargo/config.toml` supplies a local source replacement, enabled
only by the `CARGO_HOME` setting in the commands above. Cargo then generated the
lockfile and completed verification offline.

The project manifest and lockfile still use normal crates.io packages/checksums.
No local path/source override is part of the project configuration. On a machine
with registry access, use the README's ordinary `cargo ... --locked` commands.
This local cache contains only SK-01 dependencies; SK-02's new dependencies will
need fetching. Do not mistake this cache workaround for a product dependency.
