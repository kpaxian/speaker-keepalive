# SK-06 — Physical validation and milestone decision

**Status:** In progress — user-observed pulse success; measurements/inspection pending
**Prerequisite:** Read the SK-05 handoff, ticket index, and specification. The
user must be available to observe the physical JBL speaker.

## Deliverables

- Select the JBL as default output, stop the YouTube workaround and other
  playback, and establish its baseline idle shutdown time.
- Confirm routing with a one-shot test, then test default pulses for at least
  15 minutes and longer than baseline with margin.
- If needed, try 500 ms at the same amplitude, then the explicit amplitude
  progression 0.0005 → 0.001 → 0.002 → 0.005. Change one parameter at a time;
  stop increases if audible or uncomfortable. Never automate escalation.
- If pulses remain ineffective, test continuous digital silence over the same
  meaningful window. Inaudibility alone is not evidence of failure; verify the
  route and stream.
- Measure release CPU/RSS and child/backend overhead for the viable mode;
  compare both modes if both work. Check cancellation and record observations
  in `docs/hardware-validation.md`.

## Acceptance

- The user confirms whether a mode keeps the speaker powered on with acceptable
  practical inaudibility for the test window.
- Record settings, elapsed durations, power state, artifacts, resource results,
  and child cleanup. Software success does not close the hardware criterion.
- If tests are incomplete or neither mode works, leave Milestone 1 incomplete
  and record a concrete investigation rather than inventing a successful mode.
- If only silence works, report it and propose it as the operating mode. If
  both work, keep pulse mode preferred and compare measured resource use.

## Required handoff and stop condition

Record the validated mode/settings or unresolved failure, the user's actual
observations, and measurements. **Stop after Milestone 1.** Do not implement
Milestone 2 or later without the hardware result and explicit user authorization.
