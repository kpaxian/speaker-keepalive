# SK-04 — Continuous digital silence

**Status:** Complete
**Prerequisite:** Read the SK-03 handoff, ticket index, and specification.

## Deliverables

- Wire `run --mode silence` to one persistent playback child receiving only
  zero-valued PCM from a reusable fixed-size buffer.
- Pace writes through bounded pipe backpressure. Reuse cancellation, stderr
  draining, no-progress watchdog, and cleanup from SK-02.
- Restart failed streams after a fixed 30-second delay with existing diagnostic
  rate limiting. Pulse interval/options remain invalid in this mode.
- Set a stable application identifier on streams in both modes for inspection
  and future playback-activity exclusion.

## Acceptance

- A fake reader verifies zero samples and one persistent child.
- Slow/stalled readers demonstrate bounded buffering and responsive shutdown.
- Restart tests verify the delay and that the old child is reaped before its
  replacement starts.
- Appropriate formatting, tests, and Clippy pass. Replace the last temporary
  integration assertion that silence playback is unavailable.

## Session handoff — 2026-10-04

**Status:** Complete. Continuous digital silence is implemented; SK-05 is ready.

### Changes and interfaces

- `src/backend/silence.rs` starts one persistent stream with a reusable 16 KiB
  zero buffer: 2048 stereo native-endian `f32` frames, all positive zero. No
  accumulating audio queue, total-byte counter, or recurring audio files.
- `src/backend/process.rs` adds `Input::Finite` and `Input::Repeat` through
  `execute_input`. The existing `execute` API remains a finite-input wrapper.
  Repeat input retains a bounded offset, resets it at the buffer boundary, and
  keeps stdin open. Empty repeat buffers fail before spawning. Partial writes,
  backpressure, stderr drainage, cancellation, and cleanup share the same loop.
- Repeating streams have no overall timeout, but retain the 10-second
  no-progress watchdog, 100 ms maximum active poll interval, 8 KiB stderr cap,
  500 ms SIGTERM grace, and SIGKILL/reap fallback. Even a successful child exit
  is unexpected for continuous input and triggers restart handling.
- Every failed stream is fully cleaned up before an interruptible, fixed
  30-second wait starts. Capability probes happen once per run. Ctrl+C during
  the delay wakes the existing condition variable without polling.
- Extracted `Diagnostics` into `src/backend/diagnostics.rs` for both modes.
  First/changed failures log immediately; identical failures summarize at most
  once per minute. Silence resets the failure state after the replacement child
  continues accepting input for ten seconds. This is explicitly transport
  recovery, never proof of speaker delivery. A small progress callback reports
  successful writes without retaining samples or allocating a growing history.
- `Backend::playback_command` supplies shared raw PCM/unity-volume arguments plus
  `--properties` with `application.id=speaker-keepalive` and
  `application.name=speaker-keepalive` to test, pulse, and silence streams.
  Startup checks now require advertised `--properties` support.
- Extended fake-backend tests; the continuous fake validates zeros while
  discarding input, so it does not grow an audio capture file. Removed the final
  temporary unavailable-mode assertion. Updated README and ticket states.
- No dependencies, CLI options, signal bounds, or system audio settings changed.

### Protocol evidence

Installed `pw-play --help` advertises `--properties`. The full playback argument
list with the JSON properties and a final `--help` also exited successfully,
without opening an audio stream. Official documentation describes
[JSON stream properties](https://docs.pipewire.org/1.4/page_man_pw-cat_1.html)
and the [application ID key](https://docs.pipewire.org/1.4/group__pw__keys.html).
The property object is one structured argument, never shell interpolation.
Live PipeWire inspection of the resulting stream properties remains pending.

- **48 tests passed: 34 unit and 14 CLI integration tests.** The CLI suite
  includes a real 30-second restart delay and takes approximately 30.4 seconds.
- Continuous slow reads cross multiple buffer boundaries, verify all-zero
  samples, and keep one child alive. SIGINT stops slow readers and a child that
  ignores SIGTERM within the integration test's two-second shutdown bound.
- Repeat-input watchdog tests cover a stalled reader and continuous stderr
  flooding, using a shortened 300 ms test watchdog. Capture stays bounded and
  the child is reaped. Empty repeat buffers and unexpected exit status 0 fail.
- A real CLI restart test measures at least 30 seconds from the old fake's exit
  to the replacement's start, checks that the previous PID is absent, then
  verifies the replacement accepts zero PCM. Another test cancels during the
  restart wait. All recorded children are absent after shutdown, including zombies.
- Existing tests verify the exact shared command and property argument, pulse
  scheduling, finite PCM transport, failure diagnostics, and input validation.
- The first intermediate test run encountered one `ExecutableFileBusy` / “Text
  file busy” spawn error for a newly written fake. It did not recur in the full
  48-test rerun; no runtime retry workaround was added for this test-environment
  event. If it recurs, inspect fixture publication/execution before changing
  production semantics.
- Memory evidence is structural: one fixed 16 KiB audio buffer, bounded pipe
  backpressure and offset, bounded stderr/diagnostic state, and no growing audio
  files. No live RSS/CPU measurement or physical audio test was performed.
