# SK-03 — Periodic pulse runtime

**Status:** Complete
**Prerequisite:** Read the SK-02 handoff, ticket index, and specification.

## Deliverables

- Wire default `run`: generate once, play immediately, and reuse the cached
  pulse for subsequent starts.
- Anchor monotonic deadlines to the initial schedule so playback duration does
  not accumulate as drift. Allow only one playback child.
- After an overrun or missed deadlines, advance to the next future deadline.
  Never overlap pulses or replay a backlog after delay/suspend.
- Use interruptible idle waits without periodic polling or busy waiting.
- Retry transient failures on the configured schedule. After a timeout or
  overrun, also require at least one interval before retrying.
- Log the first failure, changed failure states, and recovery. Summarize
  identical repeated failures at most once per minute; verbose mode reports
  every attempt. Ordinary successful operation remains quiet.

## Acceptance

- Deterministic scheduler tests cover playback duration, overruns, large time
  jumps, missed deadlines, and retry spacing.
- Fake-backend integration tests show no overlapping children and prompt
  cancellation during idle waits and playback.
- Runtime reuses samples and writes no recurring audio files.
- Appropriate formatting, tests, and Clippy pass. Replace the temporary
  integration assertion that pulse `run` is unavailable.

### Changes and decisions

- `src/backend.rs` installs cancellation, probes capabilities, and generates and
  encodes the pulse once per run. It passes the same borrowed PCM byte buffer
  into each playback. There are no recurring audio files or new dependencies.
- New `src/backend/periodic.rs` owns the synchronous loop, pure deadline
  arithmetic, and bounded diagnostic state. Each `Backend::play` finishes and
  reaps its child before the next attempt, retaining SK-02's deadlines and
  cleanup behavior. Startup capability errors remain fatal and actionable.
- Deadlines use `Instant` and are anchored after preparation. The first pulse
  starts immediately. Normal attempts, including transient failures, use the
  next future grid slot without accumulating playback duration as drift.
- A timeout or completion at/after the following scheduled slot adds a full
  interval after completion/cleanup, rounded up to an anchored slot. Example:
  interval 1 s, completion 1.2 s => next attempt 3 s. Large jumps use constant-time
  arithmetic, never loops over missed slots. An idle wake at least one entire
  interval late skips to a future slot. Linux monotonic time excludes suspend;
  the runtime does not use wall-clock corrections or replay missed pulses.
- `Cancellation` retains its atomic active-I/O check and adds a mutex/condition
  variable for idle waits. Notification holds the same mutex as the wait check,
  preventing lost wakeups. Spurious wakes recheck cancellation and the deadline.
  Ctrl+C cancels idle waits immediately; active playback retains the 100 ms poll
  bound and 500 ms termination grace. Cleanup errors still exit unsuccessfully.
- Diagnostics compare error kind plus bounded message. First/changed failures
  log immediately, identical failures summarize at most every 60 seconds with
  suppressed counts, and recovery logs once. Verbose mode reports every attempt,
  failure/result, completion duration, and bounded successful-child stderr.
  Normal successful operation remains quiet. Retained log state is bounded.
- Extended the Python fixture with per-attempt hashes/times and a check that the
  preceding playback PID is absent before a new child starts. These files exist
  only in test fixtures; the runtime writes no audio files.
- Updated README usage/runtime semantics and ticket states. The temporary
  unimplemented assertion now covers only continuous silence.
